# 🔁 Certificate QR Replacement Bot

Batch-process **~200 certificates**: for each one, detect the existing QR code,
generate a **brand-new QR**, and paste it back at the **exact same position,
size and angle** — without touching the design, text, photo, seals or face.
All finished certificates are then **zipped**. Built to run on **Kaggle**
(free GPU/CPU), using a **Hugging Face AI model** for detection/decoding.

```
INPUT certificate (old QR)
        │
        ▼
[1] DETECT old QR  ──► WeChat CNN (🤗 opencv/qrcode_wechatqrcode)
        │               → OpenCV ArUco → geometric frame finder
        ▼
[2] BUILD payload  ──► URL that points to this certificate's image
        ▼
[3] GENERATE new QR ──► crisp high-resolution QR code
        ▼
[4] REPLACE        ──► perspective-warp new QR onto the old QR quad
        ▼               (everything else is byte-identical)
[5] VERIFY         ──► re-decode the new QR off the finished certificate
        ▼
[6] ZIP all + manifest.csv
```

---

## ⚡ Quick start on Kaggle (recommended)

1. **Upload your certificates as a Kaggle Dataset**
   (a folder of `.png/.jpg/.jpeg/.webp` images — any nesting).
2. Open **`kaggle/Cert_QR_Bot.ipynb`** in Kaggle → *File → Upload Notebook*.
3. Attach your dataset: **+ Add Input → Datasets → your certificates**.
4. Set **`BASE_URL`** in the first code cell (see *Hosting* below).
5. **Run All**. Finished certificates download as
   **`certificates_with_new_qr.zip`** in the Output panel.

> Accelerator: **CPU is enough** (~1 sec/image; 200 certs in a few minutes).
> GPU also works — the AI QR model is a tiny CPU CNN by design. A heavy
> text-to-image diffusion model is intentionally **not** used: it would *redraw*
> the certificate and risk altering names/faces. Pixel-exact warping guarantees
> "nothing else changes".

## 🖥️ Run locally

```bash
pip install -r requirements.txt
python download_models.py          # fetch WeChat CNN from Hugging Face

python run_bot.py --input ./certs --output ./done \
    --base-url https://YOUR-NAME.github.io/certificates/
# → ./certificates_with_new_qr.zip  + ./done/manifest.csv
```

### Payload modes (what the new QR encodes)

| Mode        | Effect |
|-------------|--------|
| `url` (default) | `BASE_URL + filename` → e.g. `…/certificates/031-2024-25.png`. Scanning opens that certificate image in the phone browser. |
| `csv`        | Per-cert URL/text from a spreadsheet (`filename,qr_data`). Use `--csv links.csv`. |
| `text`       | Fixed prefix + filename (`--text-prefix`). |
| `copy`       | Re-encode whatever the old QR said (if readable). |

CLI flags: `--payload-mode`, `--base-url`, `--csv`, `--text-prefix`,
`--ec {L,M,Q,H}`, `--replace-mode {full_replace,keep_frame}`,
`--output-ext {.png,.jpg}`, `--no-cnn`, `--no-debug`.

## 🌐 Hosting so scanning shows the certificate

The QR stores a **URL**, so the output images must be reachable at that URL.
Easiest free route — **GitHub Pages**:

1. Create a GitHub repo (e.g. `certificates`), upload all output images.
2. **Settings → Pages → Source = `main` / root → Save**.
3. Images are live at
   `https://<your-username>.github.io/certificates/<filename>.png`.
4. Set `BASE_URL=https://<your-username>.github.io/certificates/`.

Any host works the same (your own server, Cloudflare R2/S3, Netlify, Drive
public links…). For per-cert links use `payload_mode="csv"`.

## 🎨 AI image-generator mode (Hugging Face diffusion inpainting)

If you want the replacement performed by an **AI image model**, add `--ai`
(notebook: `USE_AI = True`). It uses **Stable Diffusion XL Inpainting**
(`diffusers/stable-diffusion-xl-1.0-inpainting-0.1`) from 🤗 Hugging Face, run
on a **Kaggle GPU (T4/P100)**, with this prompt:

> *"Generate an image of this certificate replacing only the old QR code with a
> new crisp black and white QR code in the same position. Do not change any
> design, do not change any information, do not change the face or anything
> else. Just replace the old QR code with the new QR code, keeping the
> identical certificate layout, colors, and text."*

**How it stays correct (important):** pure text-to-image can't draw a *valid*
QR — the model hallucinates plausible-looking but un-scannable blocks and may
nudge names/faces. So the bot uses **masked inpainting**: the model may only
regenerate pixels inside the old-QR square (a binary mask), and the **real,
computed QR is then composited on top** with the exact perspective warp. Result:
the edit is generated by the AI as requested, **and** the QR is guaranteed
crisp/scannable, **and** every pixel outside the mask is unchanged. If the model
can't load (CPU-only, OOM, offline), it automatically falls back to the
deterministic warp — the batch never crashes.

```bash
pip install -r requirements-ai.txt        # GPU recommended
python download_models.py
python run_bot.py --input ./certs --output ./done --ai \
    --ai-model diffusers/stable-diffusion-xl-1.0-inpainting-0.1 \
    --base-url https://YOUR-NAME.github.io/certificates/
```

Tunables: `--ai-steps` (20–40, speed vs. cleanliness), `--ai-guidance`,
`--ai-seed`, `--ai-margin`. `--ai-generative-only` returns the raw model output
for comparison (not guaranteed to scan — use only for experiments).

## 🎞️ AI "image→QR" generators (QR Code Monster ControlNet)

There are many Hugging Face / GitHub models in the **artistic-QR** family —
they take a QR matrix (plus a prompt) and let an image-diffusion model blend
art into the code. The well-known ones:

| Model | Base | Notes |
|-------|------|-------|
| `monster-labs/control_v1p_sd15_qrcode_monster` (v1/v2) | SD-1.5 ControlNet | **QR Code Monster** — the most popular; v2 blends via gray background ([HF card](https://huggingface.co/monster-labs/control_v1p_sd15_qrcode_monster)) |
| `monster-labs/control_v1p_sdxl_qrcode_monster` | SDXL ControlNet | higher-fidelity art variant |
| `AP123/IllusionDiffusion` (and qrdiffusion, DiffuseCraft) | SD-1.5 | "illusion" style QR art |

⚠️ **These are marketing/art codes, not document codes.** Per the model cards,
only **~50–80% of generations scan** — you must generate several seeds and pick
a readable one, and outputs are usually colourful/textured. For an official
certificate a **plain black-on-white QR is the correct choice** (`qr_backend="
standard"`), because it is deterministic and always scans.

The bot nevertheless includes QR Code Monster as an optional backend
(`src/qr_art.py`): it renders the exact QR matrix (error-correction **H**), runs
ControlNet over several seeds, **decodes each candidate and keeps only one that
reads back as the exact URL**, then falls back to the standard QR if none scan —
so the batch never produces a broken code.

```bash
python run_bot.py --input ./certs --output ./done \
    --qr-backend artistic --art-scale 1.5 --art-tries 6 \
    --base-url https://YOUR-NAME.github.io/certificates/
# notebook: QR_BACKEND = "artistic"   (needs GPU)
```

`--art-scale` is the scannability↔creativity dial: **1.5–1.8 = scans reliably**
(closer to a normal QR), `0.8–1.2` = more artistic but riskier. Use the
`--art-prompt` / notebook prompt for a stylised look.

## 🧠 Why these models?

- **Detection / verification AI** — `opencv/qrcode_wechatqrcode` on 🤗 Hugging
  Face (WeChat CV QR detector + super-resolution CNN). It localises and reads
  QRs even when small, rotated, JPEG-compressed or framed.
- **Fallback** — OpenCV ArUco/classic detector, then a **geometric finder**
  that locates the thick black QR *frame* via contours + finder-pattern
  checks. This is what handles certificates (like the Telangana sample) whose
  old QR is a dense/non-standard pattern that no decoder can read — the box is
  still found perfectly and replaced.
- **QR generation** — the standard `qrcode` library rendered at high
  resolution, then **perspective-warped** with area-averaged downscaling and
  re-binarised, so modules stay hard-edged and scannable even at small sizes.

### Output guarantee
Only the pixels inside the old QR quad change (measured: every other pixel is
identical to the input — verified in `tests/`). The new QR is **re-decoded off
the finished image** before a file is marked `ok`.

## 🔧 Troubleshooting

- **A file shows `recheck`/`failed`** — open `output/_debug/` (a detection
  overlay / failed image). Usually a missing/obscured QR. Re-crop those few by
  hand; the manifest lists them.
- **QR won't scan after printing** — use `--ec H` (higher error correction) and
  print ≥150 DPI; avoid scaling the certificate down.
- **Want to keep the old black border line** — `--replace-mode keep_frame`.
- **Very long URLs on tiny QRs** — shorten the base URL / use `csv` mode with
  short links; verification uses the strong WeChat decoder, so digital checks
  pass even when a phone on a low-res preview struggles (real print is larger).
